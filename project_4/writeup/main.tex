\section{Algorithm Description}
    The algorithm for this project was aimed at producing a decision tree from a subset of data so that the testing subset's error rates could be classified and compared. Specifically a Ross Quinlan 1986 ID3 greedy most information gained first implementation was used to generate a decision tree. Wherein the program will begin with a training subset size input from 1-99, wherein that many rows of data from the given 100 row dataset are randomly chosen to comprise that run or trials training subset. Once the training subset for this run has been made up, each attributes Information Gain is calculated using the entropy equation shown in Eq.~\eqref{eq:info}, which is also talked about further in the next section. The attribute with the highest calculated Information Gain is then chosen to be the root of the tree, and this is repeated until there are no attributes with non-zero information gain left from this training subset. Each row that comprises the testing subset (100 row dataset - the training subset) is then tested against this built tree, where starting at the root of the tree, the attribute is looked up in the datarow and the tree is traversed until a terminal yes or no state is seen indicating that the decision tree has decided if the robot on that run asked for help or not. The answer the tree found for that data row is recorded. Once all data rows in the testing subset are ran through the decision tree, a confusion matrix for this trial is calculated by comparing the decision trees answer (predicted) vs the data rows answer (actual). This confusion matrix allows for accuracy, recall and precision to be calculated for that trial. The program was built so that many trials at this size could be ran (all with same sized training sets but randomly made up) and the error metrics could then be averaged across the multiple runs of the same training subset size. 

\subsection*{Measuring Information}
% TODO: Explain entropy I(p1,...,pn) = -sum p_i log2(p_i) over the class distribution
% of "Decision" (Yes/No) for a set of rows, and information gain = I(parent) minus the
% size-weighted average of I(child) over the 0/1 partitions produced by splitting on a
% candidate attribute. Explain how best_attribute() picks the attribute with the
% maximum information gain at each node (the classic ID3 greedy, one-step-lookahead
% splitting rule), and why this is a greedy/local choice rather than a globally optimal
% tree search.
    The entropy calculation shown in Eq.~\eqref{eq:info} is what the algorithm uses each iteration to choose the next attribute in the tree. Entropy measures how mixed the Yes/No decisions are in a set of rows, and the Information Gain of a candidate attribute is the entropy of the rows at that node minus the size-weighted average of the entropies of the two subsets that splitting on that attribute produces. Omitting any attributes that have already been chosen that run from the calculation, it simply chooses the attribute with the highest Information Gain, meaning the attribute whose split leaves the least remaining entropy, based on the attributes and their probabilities in the comprised training subset.

\begin{equation}
    I\big(p(v_1),\dots,p(v_n)\big) \;=\; -\sum_{i} p(v_i)\,\log_2 p(v_i)
    \label{eq:info}
\end{equation}

\subsection*{Handling Undefined Cases}
% TODO: Discuss the edge cases the implementation had to special-case:
%   - p_i = 0 terms are skipped in the entropy sum (0*log2(0) is defined as 0, log2(0)
%     is undefined, so those terms are never evaluated).
%   - Empty rows subsets (a branch value that appears in 0 training rows) get
%     information() = 0 and, in build_tree, become a leaf labeled with the parent's
%     majority label (the default_label passed down the recursion) rather than
%     recursing on nothing.
%   - Pure subsets (all one class) short-circuit to a leaf immediately, no gain
%     calculation needed.
%   - Running out of attributes on a path (all 7 already used) with a still-mixed
%     class distribution: falls back to a majority-label leaf instead of splitting
%     further.
%   - Information-gain ties between candidate attributes are broken deterministically
%     by the fixed attribute order from the CSV header (first attribute in that order
%     wins), and majority-label 50/50 ties are broken by first-seen class order via
%     Counter.most_common(1) -- both choices matter for reproducibility across trials.
%   - The "full data" sweep condition (training size == all 100 rows) leaves no
%     held-out test rows; accuracy/precision/recall are left blank for that condition
%     while tree-size/depth/root-attribute are still recorded.
    There were two undefined scenarios in the information calculating and building of the tree that needed to be addressed. The first was when a class has $p_i = 0$. This will lead to Eq.~\eqref{eq:info} being undefined as $\log_2(0)$ goes to $-\infty$, also when $p_i = 0$ that term has a probability of 0 so that single term is simply skipped and not included in the entropy sum. The 2nd case being when two attributes produce valid but equal gain. The tie breaker used in this implementation was simply which attribute came first in the CSV ordering, and this was kept consistent across all runs since the CSV was structured the same throughout.

    The results clearly show that the larger the training subset, the more accurate the result of the decision tree was when tested against the testing subset across all three metrics. Also the tree size scaled significantly with the size of the training subset and the root attribute was Safe Situation in every trial at every size. Intuitively this seems like appropriate programming for a robot in regards to when it needs to ask for help or not. 

    The decision tree when ran against its own training subset it was built from had an expected 100 percent success rate so the overfitting standard trend is a bit harder to see when looking at the testing subsets trend curve, but with the addition of more data rows the trending closer to the perfect training subset does seem to start to plateau. This seems to be due to enough attributes becoming non-zero in the training subset therefore the decision trees number of nodes begin to grow no matter how little an attribute gives in regards to information. Although there is not a size in training subset where we explicitly see the testing subset start to do worse, this may be due to the limited size of the testing subset, where as the training subset grows the testing subset size shrinks and perhaps if we had more data to comprise the testing subset as the training subset and the decision tree it built grew less efficiently, the classic overfitting curve trend would be seen. To the point where between training subset sizes of 70 and 80 we see the precision metric actually get worse, where precision measures what fraction of the situations where the decision tree called for help genuinely required it, essentially the tree began producing more false positives at that point. Although asking for help in a situation where the robot did not have to is the safer direction to err in as opposed to false negatives.

    The strengths of the ID3 greedy first information based building of a decision tree is that it is a relatively simple math calculation that can be iterated over easily by computers in order to build out a pretty effective tree for coming to a conclusion. The greedy first approach is also a strength as this local focused way of choosing the next best attribute without taking into account the already built tree makes much larger training datasets possible to be used. Then the solution itself would be more accurate with the size of the training set being larger as we were able to see in the data collected above.
